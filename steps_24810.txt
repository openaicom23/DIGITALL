Order attachments on `sn_ind_tmt_orm_order`. Story: `24810.txt`. Roles: `roles_24810.txt`.

Files stay in `sys_attachment`. No new field. `sys_attachment` already has `u_document_status` with values `internal` and `external`. A file uploaded on the order is stored as `internal`. A user with `snc_external` does not see rows whose status is `internal`.

Who can do what, from `roles_24810.txt`:

- Upload and delete: `sn_ind_tmt_orm.order_admin`, `sn_ind_tmt_orm.order_agent`, `sn_ind_tmt_orm.order_fulfilment_manager`. Their descriptions are write and update on the order.
- Preview and download: every role in `roles_24810.txt`.
- `snc_external` does not see a file whose `u_document_status` is `internal`.

A second read ACL next to the existing one does not hide a file. The out-of-box rule still grants access when the user can read the order. Hiding is a Deny unless rule, plus a before-query rule, because a portal widget that uses `GlideRecord` does not apply access controls.

## 1. One script include for the roles

Create it in Global so the access rules can call it.

`sys_script_include.list`, New. Name: `OrderAttachmentAccess`. Client callable: false.

```javascript
var OrderAttachmentAccess = Class.create();
OrderAttachmentAccess.prototype = {
    initialize: function() {},

    ORDER_TABLE: 'sn_ind_tmt_orm_order',

    READ_ROLES: [
        'sn_ind_tmt_orm.fulfillment_viewer',
        'sn_ind_tmt_orm.fulfillment_writer',
        'sn_ind_tmt_orm.order_admin',
        'sn_ind_tmt_orm.order_agent',
        'sn_ind_tmt_orm.order_approver',
        'sn_ind_tmt_orm.order_creator',
        'sn_ind_tmt_orm.order_fulfilment_agent',
        'sn_ind_tmt_orm.order_fulfilment_manager',
        'sn_ind_tmt_orm.order_integrator',
        'sn_ind_tmt_orm.order_internal_contacts_user',
        'sn_ind_tmt_orm.order_internal_contact_user',
        'sn_ind_tmt_orm.order_viewer',
        'sn_ind_tmt_orm.service_order_agent',
        'sn_ind_tmt_orm.service_order_manager'
    ],

    MANAGE_ROLES: [
        'sn_ind_tmt_orm.order_admin',
        'sn_ind_tmt_orm.order_agent',
        'sn_ind_tmt_orm.order_fulfilment_manager'
    ],

    _hasAny: function(roles) {
        for (var i = 0; i < roles.length; i++) {
            if (gs.hasRole(roles[i]))
                return true;
        }
        return false;
    },

    canRead: function(attachment) {
        if (!attachment)
            return true;
        if (attachment.getValue('u_document_status') == 'internal' && gs.hasRole('snc_external'))
            return false;
        if (attachment.getValue('table_name') != this.ORDER_TABLE)
            return true;
        return this._hasAny(this.READ_ROLES);
    },

    canManage: function(attachment) {
        if (!attachment || attachment.getValue('table_name') != this.ORDER_TABLE)
            return true;
        return this._hasAny(this.MANAGE_ROLES);
    },

    isManagerOnOrder: function(attachment) {
        return !!attachment &&
            attachment.getValue('table_name') == this.ORDER_TABLE &&
            this._hasAny(this.MANAGE_ROLES);
    },

    hideFromQuery: function(current) {
        if (gs.hasRole('admin'))
            return;
        if (gs.hasRole('snc_external')) {
            var status = current.addNullQuery('u_document_status');
            status.addOrCondition('u_document_status', 'external');
            return;
        }
        if (!this._hasAny(this.READ_ROLES))
            current.addQuery('table_name', '!=', this.ORDER_TABLE);
    },

    type: 'OrderAttachmentAccess'
};
```

If `u_internal` was already added, delete that dictionary entry and any business rule that sets it. Status is `u_document_status`.

## 2. An order file is stored as internal

Create this business rule in **Global**. `sys_attachment` and `u_document_status` are global. The upload goes through the global attachment processor. A rule in `sn_ind_tmt_orm` can miss that insert and can be blocked from writing the global field.

Switch the application picker to Global, then create a business rule on `sys_attachment`:

- **When:** before
- **Insert:** checked
- **Update:** checked
- **Filter:** Table name is `sn_ind_tmt_orm_order`

```javascript
(function executeRule(current, previous) {
    current.u_document_status = 'internal';
})(current, previous);
```

The string in the script is the choice Value, not the label. If `sys_choice` for `sys_attachment.u_document_status` stores a different Value, use that Value.

Files already on orders that are not internal, run once in Scripts - Background:

```javascript
var gr = new GlideRecord('sys_attachment');
gr.addQuery('table_name', 'sn_ind_tmt_orm_order');
var qc = gr.addNullQuery('u_document_status');
qc.addOrCondition('u_document_status', '!=', 'internal');
gr.query();
while (gr.next()) {
    gr.u_document_status = 'internal';
    gr.setWorkflow(false);
    gr.autoSysFields(false);
    gr.update();
}
```

## 3. Read access

Elevate to `security_admin`. Create a **read** rule on `sys_attachment`:

- **Type:** record
- **Operation:** read
- **Decision type:** Deny unless
- **Admin overrides:** checked
- **Requires role:** empty
- **Advanced:** checked

```javascript
answer = new OrderAttachmentAccess().canRead(current);
```

A file with `u_document_status` = `internal` is denied for `snc_external`, including a direct URL. A file on `sn_ind_tmt_orm_order` passes only for a role in `READ_ROLES`. A file on another table with status `external` keeps its existing read rules.

## 4. Workspace Attachments list query

The center Attachments tab is a related list. Its query is the relationship on `sys_attachment`. Add the `snc_external` filter there. Rows with `u_document_status` = `internal` drop out of the result. Rows that are `external` or empty stay.

1. Open `sys_ui_related_list.list` for `sn_ind_tmt_orm_order` and the view the workspace uses.
2. Open the Attachments entry. Related list is `REL:` plus a sys_id.
3. Open that `sys_relationship`. Queries from table is `sys_attachment`.
4. Keep the lines that bind the file to the order. Add only the role block:

```javascript
if (gs.hasRole('snc_external')) {
    var status = current.addNullQuery('u_document_status');
    status.addOrCondition('u_document_status', 'external');
}
```

If the script only binds table and sys_id, the whole script becomes:

```javascript
(function refineQuery(current, parent) {
    current.addQuery('table_name', parent.getTableName());
    current.addQuery('table_sys_id', parent.getUniqueValue());
    if (gs.hasRole('snc_external')) {
        var status = current.addNullQuery('u_document_status');
        status.addOrCondition('u_document_status', 'external');
    }
})(current, parent);
```

The same filter is in the before-query business rule so it also applies outside this related list. If that rule already exists, update `hideFromQuery` in the script include to the version in step 1.

```javascript
(function executeRule(current, previous) {
    new OrderAttachmentAccess().hideFromQuery(current);
})(current, previous);
```

A user with `snc_external` does not see internal rows on the Attachments tab. A user with a role from `roles_24810.txt` does.

## 5. Upload and delete

Stay in Global with `security_admin` elevated. Create four separate `sys_security_acl` records. Leave **Requires role** empty on all four. Roles placed there are required together. The script checks the three manager roles one by one.

Upload and delete stay with `sn_ind_tmt_orm.order_admin`, `sn_ind_tmt_orm.order_agent`, and `sn_ind_tmt_orm.order_fulfilment_manager`. The other roles in `roles_24810.txt` preview and download.

### 5.1 Delete, Deny unless

1. Open `sys_security_acl.list` and click New.
2. Fill in:

- Type: record
- Operation: delete
- Name: `sys_attachment`
- Decision type: Deny unless
- Admin overrides: checked
- Requires role: empty
- Advanced: checked
- Description: `Order attachment delete deny unless`

3. Script:

```javascript
answer = new OrderAttachmentAccess().canManage(current);
```

4. Submit.

This blocks delete when the file is on `sn_ind_tmt_orm_order` and the user has none of the three roles. A file on another table is not blocked here.

### 5.2 Create, Deny unless

1. `sys_security_acl.list`, New.
2. Same fields as 5.1, with two changes:

- Operation: create
- Description: `Order attachment create deny unless`

3. Same script:

```javascript
answer = new OrderAttachmentAccess().canManage(current);
```

4. Submit.

This blocks upload onto the order for a user who has none of the three roles.

### 5.3 Delete, Allow if

1. `sys_security_acl.list`, New.
2. Fill in:

- Type: record
- Operation: delete
- Name: `sys_attachment`
- Decision type: Allow if
- Admin overrides: checked
- Requires role: empty
- Advanced: checked
- Condition: empty
- Description: `Order attachment delete allow if`

3. Script:

```javascript
answer = new OrderAttachmentAccess().isManagerOnOrder(current);
```

4. Submit.

This grants delete only when the file is on `sn_ind_tmt_orm_order` and the user has one of the three roles. It still grants delete when the order itself is read-only. On a file from another table this rule grants nothing.

### 5.4 Create, Allow if

1. `sys_security_acl.list`, New.
2. Same fields as 5.3, with two changes:

- Operation: create
- Description: `Order attachment create allow if`

3. Same script:

```javascript
answer = new OrderAttachmentAccess().isManagerOnOrder(current);
```

4. Submit.

This grants upload onto the order for the same three roles.

### 5.5 Write, Deny unless

1. `sys_security_acl.list`, New.
2. Same fields as 5.1, with two changes:

- Operation: write
- Description: `Order attachment write deny unless`

3. Script:

```javascript
answer = new OrderAttachmentAccess().canManage(current);
```

4. Submit.

### 5.6 Write, Allow if

1. `sys_security_acl.list`, New.
2. Same fields as 5.3, with two changes:

- Operation: write
- Description: `Order attachment write allow if`

3. Script:

```javascript
answer = new OrderAttachmentAccess().isManagerOnOrder(current);
```

4. Submit.

### File menu in the right-hand panel

The three rows in that menu are the three operations:

- Download is read. Every role in `roles_24810.txt` sees it.
- Delete is delete. Only `order_admin`, `order_agent`, and `order_fulfilment_manager` see it.
- Rename is write. The same three roles see it.

`order_viewer` and the other roles see Download only. `snc_external` does not see an `internal` file, so the menu does not open.

Impersonate `sn_ind_tmt_orm.order_viewer`. The menu on the file contains only Download. As `order_agent` it contains Download, Delete, and Rename.

If Delete or Rename is still there for `order_viewer`, the panel reads `AttachmentSecurity` instead of the access rules. Duplicate that include as `CustomAttachmentSecurity`. At the top of `canDelete` and `canWrite` add:

```javascript
if (!new OrderAttachmentAccess().canManage(current))
    return false;
```

At the top of `canRead` add:

```javascript
if (!new OrderAttachmentAccess().canRead(current))
    return false;
```

Point the read, write, and delete rules that call `AttachmentSecurity` at `CustomAttachmentSecurity`.

Filter `sys_security_acl.list` by Name is `sys_attachment`. The new rows are create, delete, and write, each with Deny unless and Allow if, next to the read rule from step 3.

## 5a. Refresh the center list after upload

The yellow button above the center Attachments tab is the related list Refresh. The right-hand panel and that list are separate components, so `+` does not press Refresh.

1. UI Builder, CSM/FSM Configurable Workspace, the Record variant for `sn_ind_tmt_orm_order`.
2. Select the right-hand Attachments component, the one with `+`.
3. Events, add a mapping for **Attachment upload succeeded**.
4. Target the center Attachments list and its **Refresh** action. That is the yellow button. Save.
5. Map **Attachment delete succeeded** to the same Refresh.

If the center list is not in the target list, the panel is a separate subpage. Create a client script on the Record page:

```javascript
function handler({api}) {
    api.emit('RECORD#RELATED_LIST_REFRESH_REQUESTED', {
        relatedListName: 'REL:PASTE_THE_RELATED_LIST_VALUE'
    });
}
```

Copy `relatedListName` from the center list configuration. It is the related list value, not the label Attachments. Add **Related list refresh requested** to the page Dispatched events when that list does not already contain it. Map both attachment events to this script.

## 7. Close the story when all of these are true

- `order_agent`, `order_admin`, and `order_fulfilment_manager` can upload, preview, download, and delete.
- The other roles in `roles_24810.txt` can preview and download.
- A file uploaded on the order has `u_document_status` = `internal`.

## Fallback when snc_external can still download the file

The download processor calls `AttachmentSecurity.canRead`. If step 6.5 still returns the file, duplicate that include as `CustomAttachmentSecurity` and add this at the top of `canRead`:

```javascript
if (!new OrderAttachmentAccess().canRead(current))
    return false;
```

Point the read ACL that calls `AttachmentSecurity` at `CustomAttachmentSecurity`.
