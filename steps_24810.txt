Order attachments stay inside FI-TS. Story: `24810.txt`.

The order manager uploads, previews, downloads, and deletes files on the order. An FI-TS employee who can open the order previews and downloads them. A user with `snc_external` does not see the files on that order and cannot open them by URL.

There is no new field on `sys_attachment`. A file is hidden because `table_name` is the order table and the user has `snc_external`.

The center Attachments tab only lists rows. Upload, preview, download, and delete are the paperclip on the right-hand rail of CSM/FSM Configurable Workspace. Both write to `sys_attachment`.

A second read ACL next to the existing one does not hide the file: the out-of-box rule still grants access when the user can read the order. Hiding is a Deny unless rule, plus a before-query rule, because a portal widget that uses `GlideRecord` does not apply access controls.

## 1. Write down the table and the order manager role

Open an order. The table name is the segment after `/record/` in the address, before the sys_id.

The order table in the scripts is `sn_ind_tmt_orm_order`. Replace `order_manager_role` with the real order manager role. Leave `snc_external` as written.

If `u_internal` was already added, delete that dictionary entry and any business rule that sets it.

## 2. Hide order files from snc_external

Elevate to `security_admin`. System Security > Access Control, or `sys_security_acl.list`.

Create a **read** rule on `sys_attachment`:

- **Type:** record
- **Operation:** read
- **Decision type:** Deny unless
- **Admin overrides:** checked
- **Requires role:** empty
- **Advanced:** checked

```javascript
var orderTable = 'sn_ind_tmt_orm_order';

if (current.getValue('table_name') == orderTable && gs.hasRole('snc_external'))
    answer = false;
else
    answer = true;
```

Deny unless is evaluated before the existing allow rules. `answer = false` denies the file, including a direct URL. `answer = true` leaves the existing read rule in place, so an FI-TS user without `snc_external` still needs to be allowed to read the order. A file on another table is outside this rule.

## 3. Hide the same files in portal lists

Portal server scripts often use `GlideRecord`, which skips access controls. Add a business rule on `sys_attachment`:

- **When:** before
- **Query:** checked
- **Insert / Update / Delete:** unchecked
- **Advanced:** checked
- **Filter:** empty

```javascript
(function executeRule(current, previous) {
    if (gs.hasRole('snc_external'))
        current.addQuery('table_name', '!=', 'sn_ind_tmt_orm_order');
})(current, previous);
```

A user with `snc_external` does not get rows for the order table. An internal user gets no extra filter.

## 4. Upload and delete for the order manager

Delete has to work when the order itself is read-only. The out-of-box delete rule follows write access on the order, so the order manager also needs an allow rule.

Create these four rules on `sys_attachment`. Leave **Requires role** empty on both Deny unless rules.

**Delete, Deny unless:**

```javascript
var orderTable = 'sn_ind_tmt_orm_order';
var managerRole = 'order_manager_role';

if (current.getValue('table_name') != orderTable)
    answer = true;
else
    answer = gs.hasRole(managerRole);
```

**Delete, Allow if:**

- **Requires role:** the order manager role
- **Condition:** Table name is `sn_ind_tmt_orm_order`
- **Script:** `answer = true;`

**Create, Deny unless:** the same script as delete.

**Create, Allow if:** the same role and condition as the delete allow rule.

An FI-TS employee who is not an order manager still passes the read rule, so preview and download stay. Delete does not. `snc_external` cannot upload a file onto the order.

## 5. Test

Use a PNG and a PDF. Impersonate each user.

1. As the order manager, open the paperclip on the right-hand rail and upload both files with Add file.
2. Preview the PNG. Download the PDF and open it.
3. Refresh the Attachments tab. Both rows are there.
4. Delete the PNG. It disappears from the panel and from the tab. The old preview URL no longer opens it.
5. Save the order and change its status. The PDF remains one row.
6. As an FI-TS employee who is not an order manager and who can open the order, preview and download the PDF. Delete is unavailable.
7. As a user with `snc_external`, open the same order in the portal. The file is not in the list and not in the activity.
8. As that user, open `/sys_attachment.do?sys_id=<pdf sys_id>` and `/api/now/attachment/<pdf sys_id>/file`. Both are denied.
9. As that user, open an attachment on another table. It still opens when that user could open it before.

## 6. Close the story when all of these are true

- The order manager can upload an attachment, and it shows on the Attachments tab.
- The order manager can preview, download, and delete it, including when the order is read-only.
- An FI-TS employee who can open the order can preview and download it.
- A user with `snc_external` does not see the order file and cannot open it by URL.

## Fallback when snc_external can still download the file

The download processor calls `AttachmentSecurity.canRead`. If step 5.8 still returns the file, that method is granting access on its own.

`AttachmentSecurity` is often read-only. Duplicate it, set the name and `type` to `CustomAttachmentSecurity`, and keep the copied logic. At the top of `canRead` add:

```javascript
if (current.getValue('table_name') == 'sn_ind_tmt_orm_order' && gs.hasRole('snc_external'))
    return false;
```

Point the existing read ACL that calls `AttachmentSecurity` at `CustomAttachmentSecurity`.
