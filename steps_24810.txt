Order attachments on `sn_ind_tmt_orm_order`. Story: `24810.txt`. Roles: `roles_24810.txt`.

Files stay in `sys_attachment`. No new field. The paperclip on the right-hand rail uploads, previews, downloads, and deletes. The Attachments tab lists the same rows.

Who can do what, from `roles_24810.txt`:

- Upload and delete: `sn_ind_tmt_orm.order_admin`, `sn_ind_tmt_orm.order_agent`, `sn_ind_tmt_orm.order_fulfilment_manager`. Their descriptions are write and update on the order.
- Preview and download: every role in `roles_24810.txt`.
- `snc_external` is not in that list, so that user does not see files on this order.

A second read ACL next to the existing one does not hide a file. The out-of-box rule still grants access when the user can read the order. Hiding is a Deny unless rule, plus a before-query rule, because a portal widget that uses `GlideRecord` does not apply access controls.

## 1. One script include for the roles

Create it in Global so the access rules can call it.

`sys_script_include.list`, New. Name: `OrderAttachmentAccess`. Client callable: false.

```javascript
var OrderAttachmentAccess = Class.create();
OrderAttachmentAccess.prototype = {
    initialize: function() {},

    ORDER_TABLE: 'sn_ind_tmt_orm_order',

    READ_ROLES: [
        'sn_ind_tmt_orm.fulfillment_viewer',
        'sn_ind_tmt_orm.fulfillment_writer',
        'sn_ind_tmt_orm.order_admin',
        'sn_ind_tmt_orm.order_agent',
        'sn_ind_tmt_orm.order_approver',
        'sn_ind_tmt_orm.order_creator',
        'sn_ind_tmt_orm.order_fulfilment_agent',
        'sn_ind_tmt_orm.order_fulfilment_manager',
        'sn_ind_tmt_orm.order_integrator',
        'sn_ind_tmt_orm.order_internal_contacts_user',
        'sn_ind_tmt_orm.order_internal_contact_user',
        'sn_ind_tmt_orm.order_viewer',
        'sn_ind_tmt_orm.service_order_agent',
        'sn_ind_tmt_orm.service_order_manager'
    ],

    MANAGE_ROLES: [
        'sn_ind_tmt_orm.order_admin',
        'sn_ind_tmt_orm.order_agent',
        'sn_ind_tmt_orm.order_fulfilment_manager'
    ],

    _hasAny: function(roles) {
        for (var i = 0; i < roles.length; i++) {
            if (gs.hasRole(roles[i]))
                return true;
        }
        return false;
    },

    canRead: function(attachment) {
        if (!attachment || attachment.getValue('table_name') != this.ORDER_TABLE)
            return true;
        return this._hasAny(this.READ_ROLES);
    },

    canManage: function(attachment) {
        if (!attachment || attachment.getValue('table_name') != this.ORDER_TABLE)
            return true;
        return this._hasAny(this.MANAGE_ROLES);
    },

    isManagerOnOrder: function(attachment) {
        return !!attachment &&
            attachment.getValue('table_name') == this.ORDER_TABLE &&
            this._hasAny(this.MANAGE_ROLES);
    },

    hideFromQuery: function(current) {
        if (gs.hasRole('admin') || this._hasAny(this.READ_ROLES))
            return;
        current.addQuery('table_name', '!=', this.ORDER_TABLE);
    },

    type: 'OrderAttachmentAccess'
};
```

If `u_internal` was already added, delete that dictionary entry and any business rule that sets it.

## 2. Read access

Elevate to `security_admin`. Create a **read** rule on `sys_attachment`:

- **Type:** record
- **Operation:** read
- **Decision type:** Deny unless
- **Admin overrides:** checked
- **Requires role:** empty
- **Advanced:** checked

```javascript
answer = new OrderAttachmentAccess().canRead(current);
```

On `sn_ind_tmt_orm_order`, only a user with a role from `READ_ROLES` passes. `snc_external` is denied, including a direct URL. A file on another table keeps its existing read rules.

## 3. Portal list

Add a before-query business rule on `sys_attachment`. Query checked. Insert, update, and delete unchecked.

```javascript
(function executeRule(current, previous) {
    new OrderAttachmentAccess().hideFromQuery(current);
})(current, previous);
```

A user with none of the roles in `roles_24810.txt` does not get rows for this order. A user with one of those roles, and admin, does.

## 4. Upload and delete

Delete has to work when the order is read-only. The out-of-box delete rule follows write access on the order.

Create four rules on `sys_attachment`. Leave **Requires role** empty on all of them. Several roles in that field are required together, and these checks are any-of.

**Delete, Deny unless** and **Create, Deny unless:**

```javascript
answer = new OrderAttachmentAccess().canManage(current);
```

**Delete, Allow if** and **Create, Allow if.** Condition empty.

```javascript
answer = new OrderAttachmentAccess().isManagerOnOrder(current);
```

That allow rule grants create or delete only to the three manage roles, and only for a file on this order.

`order_viewer`, `order_approver`, `order_fulfilment_agent`, `fulfillment_viewer`, `fulfillment_writer`, `service_order_agent`, `service_order_manager`, `order_creator`, `order_integrator`, and both internal-contact roles can preview and download. They cannot upload or delete.

## 5. Test

1. As `sn_ind_tmt_orm.order_agent`, upload a PNG and a PDF from the paperclip. Preview the PNG. Download the PDF. Both rows show on the Attachments tab. Delete the PNG.
2. Repeat upload and delete as `sn_ind_tmt_orm.order_admin` and as `sn_ind_tmt_orm.order_fulfilment_manager`.
3. As `sn_ind_tmt_orm.order_viewer`, preview and download the PDF. Upload and delete are unavailable.
4. As a user who has `snc_external` and none of the roles in `roles_24810.txt`, open the order in the portal. The file is absent.
5. As that user, open `/sys_attachment.do?sys_id=<pdf sys_id>` and `/api/now/attachment/<pdf sys_id>/file`. Both are denied.
6. As that user, open an attachment on another table. It still opens when that user could open it before.

## 6. Close the story when all of these are true

- `order_agent`, `order_admin`, and `order_fulfilment_manager` can upload, preview, download, and delete.
- The other roles in `roles_24810.txt` can preview and download.
- `snc_external` does not see the order file and cannot open it by URL.

## Fallback when snc_external can still download the file

The download processor calls `AttachmentSecurity.canRead`. If step 5.5 still returns the file, duplicate that include as `CustomAttachmentSecurity` and add this at the top of `canRead`:

```javascript
if (!new OrderAttachmentAccess().canRead(current))
    return false;
```

Point the read ACL that calls `AttachmentSecurity` at `CustomAttachmentSecurity`.
