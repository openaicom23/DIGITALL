STRY0025424 — Info an Presales nach KAM-Freigabe
След успешна KAM-Freigabe се праща един имейл до Presales Consultant на офертата.
Текст, дословно: "Folgendes Angebot wurde soeben vom KAM freigegeben:"
Плюс: Accountname, Titel der Anfrage, Nummer der Anfrage, Link.

В експорта на Quote Management Data Model тази нотификация я няма.
Ползвай съществуващите таблици и полета по-долу. Не пипай чуждите flow-ове и не възстановявай изтрития mail script fits_get_account_kam_recipients (той праща към KAM, не към Presales).

Какво вече е в системата
- Таблица на офертата: sn_quote_mgmt_core_quote
- Accountname: account.name
- Titel der Anfrage: short_description (същото поле ползва Quote KAM Approval Flow)
- Nummer der Anfrage: number
- Получател: sn_quote_mgmt_core_quote_internal_contact
  u_quote = офертата, u_rolle = Presales Consultant, u_user = потребителят
  Business rule Set Initial PreSales Consultant създава този ред при първото назначаване (assigned_to). Повторно назначаване не го презаписва.
- Път на Freigabe: бутон Submit for approval (само при state In Progress) слага state = in_approval и пуска flow sn_quote_mgmt_core.quote_kam_approval_flow.
  След одобрение офертата стига до state = approved. Имелът се закача за тази смяна, не за sysapproval_approver.
- KAM в акаунта се познава по роля fits_itil_key_account_manager. За това стори ролята служи само за теста, не за получателя.
- В експорта quote_kam_approval_flow е inactive. Преди теста провери в инстанцията. Ако и там е inactive, Freigabe няма да мине и имейлът няма какво да хване.
- Вторият експорт (Quote Management Application, sn_quote_mgmt) не съдържа тази нотификация. Потвърждава същата таблица sn_quote_mgmt_core_quote_internal_contact с полета u_quote, u_user, u_rolle.
- Там има и стандартен workspace бутон Submit for Approval. Той се крие при state approved, completed, closed, canceled и requested_for_review. Ако advanced approvals са включени, етикетът е Preview & Submit for Approval. За теста ползвай нашия бутон Submit for approval, защото той пуска quote_kam_approval_flow. Нотификацията остава върху смяната към approved, независимо кой бутон е натиснат.
- Update set-ът на сторито остава в sn_quote_mgmt_core, не в sn_quote_mgmt.

1. Update set
   Превключи приложението на Quote Management Data Model (sn_quote_mgmt_core).
   System Update Sets > Local Update Sets > New.
   Name: STRY0025424 Info an Presales nach KAM-Freigabe
   State: In progress. Make current.

2. Провери тригера в инстанцията
   Flow Designer > Quote KAM Approval Flow.
   Потвърди, че при approval approved flow-ът записва quote.state = approved.
   Ако flow-ът е inactive, не го активирай в това стори. Отбележи го: без активен flow няма Freigabe и няма как да се тества.
   Отвори една вече одобрена оферта и провери, че short_description е Titel der Anfrage. Ако заглавието е в друго поле, ползвай него в скрипта.

3. Получател без ново поле
   To се пълни преди нотификацията: business rule слага sys_id на Presales в event parm 1.
   Нотификацията има Event parm 1 contains recipient.
   Няма ново поле и няма mail script в бодито.
   Ако rule с GlideEmailOutbound вече съществува, Active = false.

4. Event
   Application picker: Quote Management Data Model.
   System Policy > Events > Registry.
   Event name, само това: quote.kam_approved
   След Save пълното име е sn_quote_mgmt_core.quote.kam_approved.
   Table: sn_quote_mgmt_core_quote.

5. Business rule
   Name: Notify Presales on KAM approval
   Table: sn_quote_mgmt_core_quote
   When: after
   Update: true
   Insert: false
   Filter: State changes to approved
   Active: true

   (function executeRule(current, previous) {
       var contactGr = new GlideRecord('sn_quote_mgmt_core_quote_internal_contact');
       contactGr.addQuery('u_quote', current.getUniqueValue());
       contactGr.addQuery('u_rolle', 'Presales Consultant');
       contactGr.setLimit(1);
       contactGr.query();
       if (!contactGr.next())
           return;
       var userId = contactGr.getValue('u_user');
       if (!userId)
           return;
       gs.eventQueue('sn_quote_mgmt_core.quote.kam_approved', current, userId);
   })(current, previous);

   Смени state на approved.

   В sys_email To е неговата поща.
   Ако SMTP на dev е спрян, записът стои в Outbox.
   Без Presales, при reject и при повторен save няма ново писмо.
