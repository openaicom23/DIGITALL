Как се изпълнява история 24810

Мениджърът на поръчката качва файл от поръчката, може да го прегледа, изтегли и изтрие. Служител на FI-TS, който отваря поръчката, може да го прегледа и изтегли. Клиентът не го вижда в портала и не може да го отвори по адрес.

Файлът стои в `sys_attachment`. Ново read правило до съществуващото не го скрива: старото правило пуска всеки, който чете поръчката. Затова има флаг FI-TS intern, правило Deny unless, и отделно query правило за списъците в портала.

## Стъпка 1. Запиши таблицата и ролите

1. Влез като администратор.
2. Отвори една поръчка.
3. В адреса на браузъра името на таблицата е думата преди `.do`. Пример: `u_order.do` означава таблица `u_order`. Запиши я.
4. Отвори потребителя клиент и потребителя на FI-TS. Запиши ролите.

В скриптовете по-долу са написани `u_order`, `order_manager_role` и `snc_external`. Смени ги с твоите.

Погледни формата на поръчката. Горе трябва да има кламер за прикачени файлове. Ако кламерът липсва, отвори таблицата и махни атрибута `no_attachment`.

## Стъпка 2. Създай флага

Работи в приложение Global. Таблицата `sys_attachment` е глобална.

1. В търсачката напиши `sys_dictionary.list` и натисни Enter.
2. Натисни New.
3. Попълни:

- Table: `sys_attachment`
- Type: True/False
- Column label: `FI-TS intern`
- Column name: `u_internal`
- Default value: `true`

4. Натисни Submit.

`true` означава, че файлът е скрит от клиента. Ако Column name се запише с префикс, използвай записаното име навсякъде надолу.

Покажи флага на поръчката:

1. Отвори поръчка.
2. Form layout, related list **Attachments**.
3. На тази related list сложи колоните File name, Content type, Size bytes, FI-TS intern, Created by.

## Стъпка 3. Флагът се слага сам при качване

1. Напиши `sys_script.list` и натисни Enter.
2. Натисни New.
3. Попълни:

- Name: `Order attachment is FI-TS intern`
- Table: `sys_attachment`
- Advanced: включено
- When: before
- Insert: включено
- Update: включено
- Filter: Table name is `u_order`

4. Скрипт:

```javascript
(function executeRule(current, previous) {
    current.u_internal = true;
})(current, previous);
```

5. Натисни Submit.

Мениджърът не пипа флага. Ако някой запис го изчисти, правилото го връща на true.

За файлове, качени преди това правило, пусни веднъж скрипт от `sys_script_fix` или от Scripts - Background. Смени таблицата.

```javascript
var gr = new GlideRecord('sys_attachment');
gr.addQuery('table_name', 'u_order');
var qc = gr.addNullQuery('u_internal');
qc.addOrCondition('u_internal', false);
gr.query();
while (gr.next()) {
    gr.u_internal = true;
    gr.setWorkflow(false);
    gr.autoSysFields(false);
    gr.update();
}
```

## Стъпка 4. Скрий файла от клиента

Преди да създаваш права, вдигни роля `security_admin`: иконата на потребителя, Elevate Roles, `security_admin`.

1. Напиши `sys_security_acl.list` и натисни Enter.
2. Натисни New.
3. Попълни:

- Type: record
- Operation: read
- Name: таблица `sys_attachment`
- Decision type: Deny unless
- Admin overrides: включено
- Requires role: празно
- Advanced: включено

Роля на това правило би спряла и служителите на FI-TS по други таблици. Скриптът важи само за поръчката.

```javascript
var orderTable = 'u_order';
var customerRole = 'snc_external';

function isInternal(att) {
    var v = att.getValue('u_internal');
    return v == '1' || v == 'true';
}

if (current.getValue('table_name') != orderTable) {
    answer = true;
} else if (!isInternal(current)) {
    answer = true;
} else if (gs.hasRole(customerRole)) {
    answer = false;
} else {
    answer = true;
}
```

4. Натисни Submit.

Ако клиентът няма роля `snc_external` и няма никаква роля, този `hasRole` не го хваща. Тогава последният клон става така, с вътрешните роли от стъпка 1:

```javascript
} else if (gs.hasRole('order_manager_role') || gs.hasRole('itil')) {
    answer = true;
} else {
    answer = false;
}
```

`answer = false` спира клиента дори старото read правило да го пуска. `answer = true` оставя старото правило: служител на FI-TS вижда файла само ако вече може да отвори поръчката.

Ако на формата няма поле Decision type, мини на последната секция.

## Стъпка 5. Скрий файла и в списъците на портала

Виджет в портала често чете с `GlideRecord` и прескача правата. Затова има второ business rule.

1. Отново `sys_script.list`, New.
2. Попълни:

- Name: `Hide FI-TS intern attachments from customer`
- Table: `sys_attachment`
- Advanced: включено
- When: before
- Query: включено
- Insert, Update, Delete: изключени
- Filter: празно

```javascript
(function executeRule(current, previous) {
    if (gs.hasRole('snc_external'))
        current.addQuery('u_internal', '!=', true);
})(current, previous);
```

3. Смени ролята с клиентската от стъпка 1.
4. Натисни Submit.

На вътрешен потребител това правило не добавя филтър. Кламерът, прегледът и изтеглянето за FI-TS остават.

## Стъпка 6. Качване и изтриване само за мениджъра на поръчката

Изтриването трябва да работи и когато поръчката е само за четене. Старото delete правило гледа дали потребителят пише по поръчката. Затова освен Deny unless има и едно Allow if за мениджъра.

Създай четири правила на `sys_attachment`. И при двете Deny unless остави Requires role празно.

**Delete, Deny unless.** Operation: delete. Decision type: Deny unless.

```javascript
var orderTable = 'u_order';
var managerRole = 'order_manager_role';

if (current.getValue('table_name') != orderTable)
    answer = true;
else
    answer = gs.hasRole(managerRole);
```

**Delete, Allow if.** Operation: delete. Decision type: Allow if.

- Requires role: ролята на мениджъра на поръчката
- Condition: Table name is `u_order`
- Script: `answer = true;`

**Create, Deny unless.** Същият скрипт като при delete.

**Create, Allow if.** Същата роля и същото условие като Allow if за delete.

Служител на FI-TS, който не е мениджър, минава read правилото от стъпка 4 и може да преглежда и тегли. Delete правилото го спира.

## Стъпка 7. Преглед и изтегляне

Класическа форма: кламерът отваря Manage Attachments. Оттам се качва, преглежда, тегли и трие.

Workspace: панелът за файлове на поръчката прави същите четири неща и пише в същата `sys_attachment`. Флагът и правилата важат и там.

Прегледът ползва read. За PNG и PDF бутонът View отваря файла. Download го сваля.

В портала не се прави нова страница. Списъкът и активността четат `sys_attachment`. Редовете с флага отпадат, а директният адрес се отказва от стъпка 4.

Ако след стъпка 8 в портала още се вижда името на файла, виджетът си пази отделен списък. Отвори го и добави:

```javascript
gr.addQuery('u_internal', '!=', true);
```

Или смени заявката на `GlideRecordSecure`.

## Стъпка 8. Провери

Приготви един PNG и един PDF. Между проверките влизай с Impersonate. За `sys_attachment` се върни като администратор.

1. Като мениджър на поръчката качи двата файла от кламера или от панела във Workspace.
2. В related list Attachments и двата реда имат FI-TS intern = true.
3. Прегледай PNG. Изтегли PDF и го отвори.
4. Изтрий PNG. Редът изчезва от related list и от `sys_attachment.list`. Старият адрес за преглед вече не отваря файла.
5. Запиши поръчката и смени статуса, без ново качване. PDF остава един.
6. Като служител на FI-TS, който не е мениджър и може да отвори поръчката, прегледай и изтегли PDF. Изтриване няма.
7. Като клиент отвори същата поръчка в портала. Файлът го няма в списъка и го няма в активността.
8. Като клиент отвори `/sys_attachment.do?sys_id=<sys_id на pdf>` и `/api/now/attachment/<sys_id>/file`. И двата адреса се отказват.
9. Като вътрешен потребител отвори прикачен файл на друга таблица, например инцидент. Той се отваря. Новите правила важат за таблицата на поръчката.

## Историята е готова, когато

- мениджърът качва файл на поръчката
- мениджърът го преглежда, тегли и трие, включително при поръчка само за четене
- служител на FI-TS, който отваря поръчката, го преглежда и тегли
- на файла FI-TS intern е true
- клиентът не вижда файла в портала и не го отваря по адрес

## Ако клиентът все пак сваля файла

Прозорецът и свалянето викат script include `AttachmentSecurity`, метод `canRead`. Ако в стъпка 8 клиентът получи файла, този метод го пуска отделно от правата.

Include-ът често е Read-only. Дублирай го. Новото име и `type` са `CustomAttachmentSecurity`. Запази копираната логика. Най-отгоре в `canRead`, преди нея, сложи:

```javascript
var v = current.getValue('u_internal');
var isInternal = v == '1' || v == 'true';
if (current.getValue('table_name') == 'u_order' && isInternal && gs.hasRole('snc_external'))
    return false;
```

Намери съществуващото read правило, чийто скрипт вика `AttachmentSecurity`, и го насочи към `CustomAttachmentSecurity`. Правилото остава активно за другите таблици: новите редове връщат false само за файл с флаг върху поръчка, когато потребителят е клиентът.
