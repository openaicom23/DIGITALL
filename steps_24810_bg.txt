Как се изпълнява история 24810

Поръчката се отваря в CSM/FSM Configurable Workspace. Кламерът в дясната лента качва, преглежда, тегли и трие. Табът Attachments в средата е списъкът на същите файлове.

## Какво иска заданието

1. Мениджърът на поръчката качва файл към поръчката, когато му трябва.
2. Мениджърът може да изтрие файла по всяко време.
3. Служител на FI-TS може по всяко време да отвори и да изтегли файла.
4. Клиентът не вижда файла в портала и не може да го отвори по адрес.
5. На всеки файл има флаг, който го прави невидим за клиента.
6. Проверени са качване, преглед и изтриване.

## Какво вече е на екрана

Кламерът вдясно прави качване, преглед, изтегляне и изтриване. Табът Attachments показва качените файлове. И двете места пишат в `sys_attachment`.

Остава флагът и забраната за клиента. Без тях клиент, който чете поръчката, вижда и файла.

## Стъпка 1. Запиши таблицата и ролите

1. Отвори поръчка в workspace.
2. В адреса след `/record/` е таблицата, после sys_id. Запиши таблицата.
3. Запиши ролята на мениджъра на поръчката и ролята на клиента в портала. Често клиентската е `snc_external`.

В скриптовете долу са `u_order`, `order_manager_role` и `snc_external`. Смени ги с твоите.

## Стъпка 2. Създай флага

Работи в Global. `sys_attachment` е глобална таблица.

1. Напиши `sys_dictionary.list` и натисни Enter.
2. New.
3. Попълни:

- Table: `sys_attachment`
- Type: True/False
- Column label: `FI-TS intern`
- Column name: `u_internal`
- Default value: `true`

4. Submit.

`true` означава, че файлът е само за FI-TS. Ако Column name се запише с префикс, ползвай записаното име навсякъде надолу.

Сложи колоната на списъка, който вече виждаш:

1. Отвори поръчката и таб Attachments.
2. С десен бутон върху заглавие на колона избери Configure > List Layout. Ако менюто липсва, отвори `sys_ui_list.list`, намери изгледа на `sys_attachment` за тази related list и добави колоната там.
3. Добави `FI-TS intern` до File name.

## Стъпка 3. Флагът се слага сам при качване

1. `sys_script.list`, New.
2. Попълни:

- Name: `Order attachment is FI-TS intern`
- Table: `sys_attachment`
- Advanced: включено
- When: before
- Insert: включено
- Update: включено
- Filter: Table name is таблицата от стъпка 1

3. Скрипт:

```javascript
(function executeRule(current, previous) {
    current.u_internal = true;
})(current, previous);
```

4. Submit.

За файлове, качени преди правилото, пусни веднъж Scripts - Background:

```javascript
var gr = new GlideRecord('sys_attachment');
gr.addQuery('table_name', 'u_order');
var qc = gr.addNullQuery('u_internal');
qc.addOrCondition('u_internal', false);
gr.query();
while (gr.next()) {
    gr.u_internal = true;
    gr.setWorkflow(false);
    gr.autoSysFields(false);
    gr.update();
}
```

Смени `u_order` с таблицата от стъпка 1.

## Стъпка 4. Скрий файла от клиента

Преди правата: иконата на потребителя, Elevate Roles, `security_admin`.

Ново read правило до старото не стига. Старото пуска всеки, който чете поръчката. Затова правилото е Deny unless.

1. `sys_security_acl.list`, New.
2. Попълни:

- Type: record
- Operation: read
- Name: `sys_attachment`
- Decision type: Deny unless
- Admin overrides: включено
- Requires role: празно
- Advanced: включено

3. Скрипт:

```javascript
var orderTable = 'u_order';
var customerRole = 'snc_external';

function isInternal(att) {
    var v = att.getValue('u_internal');
    return v == '1' || v == 'true';
}

if (current.getValue('table_name') != orderTable) {
    answer = true;
} else if (!isInternal(current)) {
    answer = true;
} else if (gs.hasRole(customerRole)) {
    answer = false;
} else {
    answer = true;
}
```

4. Submit.

Ако клиентът няма роля, последният клон става така, с вътрешните роли от стъпка 1:

```javascript
} else if (gs.hasRole('order_manager_role') || gs.hasRole('itil')) {
    answer = true;
} else {
    answer = false;
}
```

`answer = false` спира клиента. `answer = true` оставя старото правило: служител на FI-TS вижда файла, когато вече може да отвори поръчката.

Ако на формата няма Decision type, мини на последната секция.

## Стъпка 5. Скрий файла и в списъка на портала

Виджет в портала често чете с `GlideRecord` и прескача правата.

1. `sys_script.list`, New.
2. Попълни:

- Name: `Hide FI-TS intern attachments from customer`
- Table: `sys_attachment`
- Advanced: включено
- When: before
- Query: включено
- Insert, Update, Delete: изключени
- Filter: празно

```javascript
(function executeRule(current, previous) {
    if (gs.hasRole('snc_external'))
        current.addQuery('u_internal', '!=', true);
})(current, previous);
```

3. Смени ролята с клиентската от стъпка 1.
4. Submit.

## Стъпка 6. Изтриване само за мениджъра на поръчката

Изтриването трябва да работи и когато поръчката е само за четене. Старото delete правило гледа дали потребителят пише по поръчката. Затова има Deny unless и едно Allow if.

Четири правила на `sys_attachment`. При двете Deny unless Requires role остава празно.

**Delete, Deny unless.** Operation: delete. Decision type: Deny unless.

```javascript
var orderTable = 'u_order';
var managerRole = 'order_manager_role';

if (current.getValue('table_name') != orderTable)
    answer = true;
else
    answer = gs.hasRole(managerRole);
```

**Delete, Allow if.** Operation: delete. Decision type: Allow if.

- Requires role: ролята на мениджъра
- Condition: Table name is таблицата от стъпка 1
- Script: `answer = true;`

**Create, Deny unless.** Същият скрипт като при delete.

**Create, Allow if.** Същата роля и същото условие като Allow if за delete.

Служител на FI-TS, който не е мениджър, преглежда и тегли. Изтриването остава за мениджъра.

## Стъпка 7. Провери качване, преглед и изтриване

Приготви един PNG и един PDF.

1. Като мениджър отвори поръчка. Натисни кламера в дясната лента.
2. С Add file качи двата файла.
3. Отвори менюто на PNG и го прегледай. Изтегли PDF и го отвори.
4. Опресни таб Attachments. И двата реда са там, FI-TS intern е true.
5. От кламера изтрий PNG. Редът изчезва от панела и от таба. Старият адрес за преглед не отваря файла.
6. Запиши поръчката и смени статуса. PDF остава един.
7. Като служител на FI-TS, който не е мениджър и може да отвори поръчката, прегледай и изтегли PDF. Изтриване няма.
8. Като клиент отвори същата поръчка в портала. Файлът го няма в списъка и го няма в активността.
9. Като клиент отвори `/sys_attachment.do?sys_id=<sys_id на pdf>` и `/api/now/attachment/<sys_id>/file`. И двата адреса се отказват.
10. Като вътрешен потребител отвори прикачен файл на друга таблица. Той се отваря.

## Историята е готова, когато

- мениджърът качва файл от кламера и редът се вижда в таб Attachments
- мениджърът преглежда, тегли и трие, включително при поръчка само за четене
- служител на FI-TS преглежда и тегли
- на файла FI-TS intern е true
- клиентът не вижда файла в портала и не го отваря по адрес

## Ако клиентът все пак сваля файла

Свалянето вика script include `AttachmentSecurity`, метод `canRead`. Ако стъпка 7.9 върне файла, този метод го пуска отделно от правата.

Include-ът често е Read-only. Дублирай го. Новото име и `type` са `CustomAttachmentSecurity`. Запази копираната логика. Най-отгоре в `canRead` сложи:

```javascript
var v = current.getValue('u_internal');
var isInternal = v == '1' || v == 'true';
if (current.getValue('table_name') == 'u_order' && isInternal && gs.hasRole('snc_external'))
    return false;
```

Намери read правилото, чийто скрипт вика `AttachmentSecurity`, и го насочи към `CustomAttachmentSecurity`.
