Story 25824 — Neuer Tab "Genehmigungen"

Source: `25824/update_sets.txt`, captured by IZEAE65. Story: `25824/story.txt`.

On Quote (`sn_quote_mgmt_core_quote`) the related list **Genehmigungen** shows the `sysapproval_approver` rows for that Quote. The link is `source_table` + `document_id`, not `sysapproval`. Open, approved, and rejected rows all stay in the list. The newest change is first.

No new table. No new Approve or Reject button. No ACL. No change to the `state` choices.

The file contains six payloads. The list layout is pasted twice; it is one record.

## Relationship

`sys_relationship` **Genehmigungen**, sys_id `4d1f659568c81f10b0e4e691f7bdbeba`.

- Applies to: `sn_quote_mgmt_core_quote`
- Queries from: `sysapproval_approver`
- Application: Quote Management Data Model (`sn_quote_mgmt_core`)
- Created 2026-10-19 14:46, updated 2026-10-20 12:22

```javascript
(function refineQuery(current, parent) {
    current.addQuery('source_table', 'sn_quote_mgmt_core_quote');
    current.addQuery('document_id', parent.sys_id);
    current.orderByDesc('sys_updated_on');
})(current, parent);
```

There is no filter on `state`, so a rejected approval remains on the tab. `sys_updated_on` descending is the Zeitpunkt: approve and reject update that field, and the latest row is at the top.

The relationship name is the tab title.

## What this update set does not contain

- No read or write ACL on `sysapproval_approver`. A user sees a row when the existing approval ACLs allow it.
- No UI action. Approve and Reject (Genehmigen / Ablehnen) are the existing buttons on the approval record. They show when `state` is `requested` and the logged-in user is `approver`.
- No record that creates an approval. The tab only lists rows that already exist, linked by `source_table` = `sn_quote_mgmt_core_quote` and `document_id` = the Quote sys_id.

## Story criteria against this update set

- The tab **Genehmigungen** is on Default view, LBBW Quote, CSM FSM Configurable Workspace, and SOM Workspace, with no role on the related list.
- On SOM Workspace the list shows `state` and `sys_updated_on`, and it includes every state because the relationship does not filter `state`.
- The row opens `sysapproval_approver`. Approval and rejection are the existing buttons on that record.

## Test fix

INT test with `SOM_Presales_1`: the tab and the list are correct, and a user who is not `approver` can still set `state` to `approved` on the workspace form. The activity on QT0001123 shows that user changed Status from Angefordert to Genehmigt while Genehmiger stayed Michaela Tusche.

An extra Allow write ACL does not stop this. The rule that already grants write still grants it. `25824/steps_fix_bg.txt` adds three records in Global:

- Script include `QuoteApprovalGuard`
- Before update business rule on `sysapproval_approver`, because a UI action calls `current.update()` and skips ACLs
- Deny unless write on `sysapproval_approver.state` and on `sysapproval_approver.approver`

KAM sees the story: the Genehmigungen tab, every quote approval row, the status, and the time. That does not require `approval_admin` or `sn_quote_mgmt_core.quote_admin`. A quote approval row is readable when the user can read that Quote. A user who cannot read the Quote does not see its rows. The tab stays on the Quote form, with no role of its own.

Only the stored approver, an active approval delegate, `admin`, or `system` can set `approved` or `rejected`, or change `approver`, on a quote approval. `quote_admin` and `approval_admin` do not decide a row unless that user is the stored approver. A UI policy locks those two fields on the form when the logged-in user is not the approver and `source_table` is `sn_quote_mgmt_core_quote`. Other approval tables stay unchanged. `cancelled` is not blocked.

## Кой одобрява и отказва заявката

KAM вижда таб Genehmigungen, всички редове по Quote, Status и часа. Отваря реда. За това не му трябва отделна роля за одобрение. Ред към Quote се чете само от потребител, който чете тази Quote. Който не я чете, не вижда нейните редове.

За Genehmigung към Quote (`sn_quote_mgmt_core_quote`, запис в `sysapproval_approver` със статус Angefordert / `requested`) одобряване (Genehmigt / `approved`) и отказ (Abgelehnt / `rejected`) минават само за:

- потребителят, който вече е записан в Approver (Genehmiger)
- активен негов делегат, при когото Approvals е включено и периодът на делегирането включва текущия момент
- потребител с роля `admin`
- потребител `system` (flow)

KAM, който не е този Genehmiger, вижда статуса и не одобрява чужда заявка. Същото е за `sn_quote_mgmt_core.quote_admin` и `approval_admin`, когато потребителят не е записан в Approver. Бутоните Genehmigen и Ablehnen за него са скрити. Смяна на статуса към `cancelled` не се спира. Genehmigung, която не е за Quote, не се пипа.

## Who can approve and reject the request

KAM sees the Genehmigungen tab, every row for the Quote, the status, and the time. Opening the row does not require an approval role.

On a quote approval (`sn_quote_mgmt_core_quote`, a `sysapproval_approver` row in state Angefordert / `requested`), approve (Genehmigt / `approved`) and reject (Abgelehnt / `rejected`) are allowed only for:

- the user already stored in Approver (Genehmiger)
- an active delegate of that user, with Approvals enabled, whose delegation period includes the current time
- a user with the `admin` role
- the `system` user (flows)

A KAM who is not that Genehmiger sees the status and cannot approve someone else's request. The same applies to `sn_quote_mgmt_core.quote_admin` and `approval_admin` when that user is not the stored approver. The Genehmigen and Ablehnen buttons are hidden for them. A change to `cancelled` is not blocked. An approval that is not for a Quote is left unchanged.
