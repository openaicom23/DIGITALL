Тест с Test User SOM_Presales_1, Quote QT0001123, CSM/FSM Configurable Workspace.

Минава:

- списъкът показва Genehmigungen и на други хора

Не минава:

- в Activity стои, че SOM_Presales_1 е сменил Status от Angefordert на Genehmigt

Формата на `sysapproval_approver` в Workspace има поле Status. Записът минава, защото някое съществуващо write правило пуска този потребител. Ново Allow write правило не го спира: стига едно Allow да мине и писането е позволено. Затова тук се слага Deny unless. То се гледа преди Allow.

Бутон Approve вика `current.update()` и подминава ACL. Затова същото условие стои и в before business rule.

Работи в Global. За двете ACL вдигни роля `security_admin`.

KAM вижда това, което иска сторито: таб Genehmigungen, всеки ред по Quote (отворен, одобрен, отказан), Status и часа. За това не му трябва `approval_admin` или `sn_quote_mgmt_core.quote_admin`. Ако списъкът за него е празен, а за admin не е, четенето е в стъпка 5 на `25824/steps_bg.txt`. Това ACL пуска четене и не пуска одобрение.

Кой може да смени Status на Genehmigt или Abgelehnt, или да смени Genehmiger, върху Genehmigung за Quote:
- потребителят, който вече е записан в Approver
- активен негов делегат с включени approvals
- `admin`
- `system`

KAM, който не е този Genehmiger, отваря реда и вижда статуса. Запис на Genehmigt или Abgelehnt не минава. Същото важи за потребител с `sn_quote_mgmt_core.quote_admin` или `approval_admin`, ако не е записан в Approver. Смяна към `cancelled` не се спира. Genehmigung, която не е за `sn_quote_mgmt_core_quote`, не се пипа.

## Стъпка 1. Script Include

1. Превключи приложението на Global.
2. `sys_script_include.list`, New.
3. Name: `QuoteApprovalGuard`
4. Client callable: изключено
5. Скрипт:

```javascript
var QuoteApprovalGuard = Class.create();
QuoteApprovalGuard.prototype = {
    initialize: function() {},

    QUOTE_TABLE: 'sn_quote_mgmt_core_quote',

    isQuoteApproval: function(rec) {
        if (!rec)
            return false;
        if (rec.getValue('source_table') == this.QUOTE_TABLE)
            return true;
        var taskId = rec.getValue('sysapproval');
        if (!taskId)
            return false;
        var task = new GlideRecord('task');
        if (!task.get(taskId))
            return false;
        return task.getValue('sys_class_name') == this.QUOTE_TABLE;
    },

    canDecide: function(rec) {
        if (!rec)
            return false;
        if (gs.getUserName() == 'system')
            return true;
        if (gs.hasRole('admin'))
            return true;
        var approverId = rec.getValue('approver');
        if (!approverId)
            return false;
        if (approverId == gs.getUserID())
            return true;
        return this._isActiveApprovalDelegate(approverId);
    },

    canWriteState: function(rec) {
        if (!this.isQuoteApproval(rec))
            return true;
        var state = rec.getValue('state');
        if (state != 'approved' && state != 'rejected')
            return true;
        return this.canDecide(this._stored(rec));
    },

    canWriteApprover: function(rec) {
        if (!this.isQuoteApproval(rec))
            return true;
        return this.canDecide(this._stored(rec));
    },

    canRead: function(rec) {
        if (!this.isQuoteApproval(rec))
            return true;
        var quoteId = this._quoteId(rec);
        if (!quoteId)
            return false;
        var quote = new GlideRecord(this.QUOTE_TABLE);
        if (!quote.get(quoteId))
            return false;
        return quote.canRead();
    },

    blockUnauthorizedDecision: function(current, previous) {
        if (!this.isQuoteApproval(current))
            return;
        if (this.canDecide(previous))
            return;

        var newState = current.getValue('state');
        var setsOutcome = current.state.changes() && (newState == 'approved' || newState == 'rejected');
        var movesApprover = current.approver.changes();
        if (!setsOutcome && !movesApprover)
            return;

        gs.addErrorMessage('Nur der eingetragene Genehmiger darf diese Genehmigung genehmigen oder ablehnen.');
        current.setAbortAction(true);
    },

    _quoteId: function(rec) {
        if (rec.getValue('source_table') == this.QUOTE_TABLE && rec.getValue('document_id'))
            return rec.getValue('document_id');
        return rec.getValue('sysapproval');
    },

    _stored: function(rec) {
        var stored = new GlideRecord('sysapproval_approver');
        if (stored.get(rec.getUniqueValue()))
            return stored;
        return rec;
    },

    _isActiveApprovalDelegate: function(approverId) {
        var now = new GlideDateTime();
        var del = new GlideRecord('sys_user_delegate');
        del.addQuery('user', approverId);
        del.addQuery('delegate', gs.getUserID());
        del.addQuery('approvals', true);
        del.query();
        while (del.next()) {
            var starts = del.getValue('starts');
            if (starts) {
                var startAt = new GlideDateTime(starts);
                if (startAt.compareTo(now) > 0)
                    continue;
            }
            var ends = del.getValue('ends');
            if (ends) {
                var endAt = new GlideDateTime(ends);
                if (endAt.compareTo(now) < 0)
                    continue;
            }
            return true;
        }
        return false;
    },

    type: 'QuoteApprovalGuard'
};
```

6. Submit.

`canWriteState` и `canWriteApprover` гледат Genehmiger, който вече е в базата. Иначе заявката първо сменя Genehmiger на себе си и после минава проверката.

Датите на делегирането се гледат в цикъла, не с `addOrCondition`. В encoded query `^OR` цепи цялата заявка: `(user AND delegate AND approvals AND starts празно) OR starts<=сега OR ends>=сега`. Ако в `sys_user_delegate` има ред с крайна дата напред, `hasNext()` е true за всеки потребител и той минава като делегат. Затова потребител, който не е Genehmiger, записва Abgelehnt.

## Стъпка 4.1. Редът се чете само ако се чете Quote

Табът стои на Quote, затова го вижда който е отворил Quote. Редът в `sysapproval_approver` се отваря и от списъка на одобренията, от търсене и по директен линк. Allow read не спира това: стига едно съществуващо Allow да мине и редът се вижда. Затова тук е Deny unless.

- Operation: read
- Name: `sysapproval_approver`

- Advanced: включено
- Description: `Quote approval read deny unless quote reader`

За Genehmigung към Quote редът се вижда само когато `quote.canRead()` е true. KAM, който чете Quote, вижда всичките й редове в таба. Потребител, който не чете тази Quote, не вижда нейните редове. ## Стъпка 5. Полетата на формата са само за четене

ACL на `state` пуска полето, докато стойността още е Angefordert, и отказва чак при запис на Genehmigt. Без това правило падащото меню остава активно. UI policy го заключва веднага за човек, който не е Genehmiger.

В операторите няма `is not (dynamic)`. Има само `is (dynamic)`, най-отдолу в списъка. На немски е `ist (dynamisch)`. След него третото поле е списък, не търсене на потребител. Избери `Me` (`Ich`).

Правят се две policy. Първата заключва полетата на всяка Quote Genehmigung. Втората ги отключва само когато Genehmiger е влезлият потребител. По-големият Order печели.

## Стъпка 7. Скрий бутоните само на тази форма

UI policy пипа полета. Genehmigen и Ablehnen не са полета и policy не може да ги скрие.

UI actions са много, защото списъкът съдържа и менютата на списъка. Нов бутон не маха зелените и червените. Затова тук нищо в `sys_ui_action` не се променя.

Скриптът върви само когато се отвори формата на `sysapproval_approver`. На списъци и на други таблици не върви. Ако редът не е Genehmigung към Quote, скриптът излиза веднага и бутоните остават както са.

Бутоните остават за записания Genehmiger и за негов активен делегат. Потребител с `admin` ги вижда и когато не е Genehmiger. KAM, `quote_admin` и `approval_admin` не ги виждат на чужд ред. Проверката е с Test User SOM_Presales_1.
